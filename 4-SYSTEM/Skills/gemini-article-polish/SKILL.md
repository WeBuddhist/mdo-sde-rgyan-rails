# gemini-article-polish

Takes a finished, verified `article.md` (the `wiki-article-from-claims` output convention) and asks **Gemini** — whose native Tibetan composition is stronger than the drafting model's — to recompose the prose only: word order, clause structure, idiom, discourse flow. The facts are frozen. This is an experimental extra pass (2026-08-21, not part of the IATS paper pipeline) to measure how much a stronger Tibetan writer improves the reading experience without re-opening any verified content.

The skill prevents the one failure mode that matters: **silent factual drift under the cover of restyling.** Three layers guard it: (1) every `<ref>` is replaced by an opaque token before Gemini sees the text, and the frozen tail is never sent at all; (2) the bundled script's deterministic checks C1–C7 (token conservation, heading sequence, verbatim quotations, no commas, no Latin, shad-before-ref, bold spans) block mechanically detectable drift; (3) the executing agent performs a sentence-by-sentence **semantic diff** of before vs after — any added, dropped, weakened, strengthened, or re-attributed fact is a FAIL. Correct output is an article a Tibetan reader experiences as noticeably more natural prose that a fact-checker cannot distinguish from the original in content.

This skill writes vault files only, never publishes, and by default never overwrites the canonical article — output goes to a pilot folder for domain-expert review.

---

## Inputs

1. **Topic path(s)** — the folder of an existing article: `3-TRANSFORMATIONS/Wikipedia/<text-slug>/slot-articles/<topic>/` or `term-articles/<topic>/`, containing a verified `article.md` and its `citations.md`. If either file is missing, stop and report.
2. **Output mode** — `pilot` (default): write to `3-TRANSFORMATIONS/Wikipedia/<text-slug>/work/pilot-gemini/<topic>/`. `in-place` only on explicit human instruction (after the pilot has been reviewed and accepted).
3. **API key** — `GEMINI_API_KEY`, resolved by the script from the environment, then a vault-local `.env`, then the shell profile. **This skill is the only one in the article chain that needs a key**, and it needs network access to the Gemini API. Never echo, log, or write the key anywhere.
4. **The bundled script** — `4-SYSTEM/Skills/gemini-article-polish/scripts/gemini_polish.py` (the only thing that talks to the network).
5. **The preview generator** — `4-SYSTEM/Skills/wiki-article-from-claims/scripts/make_preview.py`, to regenerate `article-preview.md` from the polished article.

## Output

Per topic, under the output folder (`work/pilot-gemini/<topic>/` in pilot mode):

```
article.md          polished article — original frontmatter + callout, recomposed fence
                    body, plus polish provenance keys (polished_by, polish_model,
                    polish_date, polish_source)
citations.md        copied from the source topic folder with a `polish:` header note —
                    the audit trail is unchanged because no claim usage changed
article-preview.md  regenerated by make_preview.py from the polished article.md
gemini-report.md    script-written: model, attempts, C1–C7 results, warnings
semantic-diff.md    agent-written: the sentence-level fact comparison and its verdict
body-before.txt     script-written diff aids (editable prose before/after)
body-after.txt
```

## Rules

1. **Facts are frozen.** The polished article must contain exactly the factual content of the source — nothing added (however standard), nothing dropped, nothing weakened or strengthened, no position re-attributed to a different commentator. The consolidated claims page and raw claims files are **not consulted** — the source article is the complete factual contract.
2. **Refs are frozen in content and reviewed in attachment.** The script guarantees every `<ref>` survives character-for-character (token conservation, C1). The agent must additionally verify each ref still sits on the statement its claims support — a ref migrated onto a different assertion is factual drift and a FAIL, even though C1 passes.
3. **Verbatim quotations are untouchable** — character-for-character, enforced by C3 and re-confirmed in the semantic diff.
4. **The punctuation contract and wikitext mechanics of `wiki-article-from-claims` (Rules 11, 15–17) still bind.** No commas, sentence-final shad, paragraph-final double shad, punctuation before refs, Tibetan-only body, headings/tail/category untouched, `author_in_use` name forms preserved exactly as they appear in the source prose.
5. **Only the script talks to Gemini.** No ad-hoc API calls; no pasting article text into other tools. The API key is never echoed, logged, or written to any file.
6. **Pilot mode is the default.** The canonical topic folder is written only in `in-place` mode on explicit human instruction. In pilot mode nothing outside `work/pilot-gemini/<topic>/` is modified.
7. **A hard-check FAIL after the script's retries stops the topic.** Report it; never hand-patch Gemini's output to force the checks green — the recomposition is either mechanically clean or rejected.
8. **The semantic diff separates flaggable substitutions from factual drift.** A **lexical substitution** — same referent, arguably same meaning (an idiom swap, a spelling normalisation, a grammar-particle change) — is recorded in `semantic-diff.md` §Flagged substitutions with both forms side by side, for the domain expert to accept or reject; the verdict can still be PASS. **Factual drift** — a different fact, a different position-holder, content added or dropped, a quotation or name altered — is a FAIL with three remedies, in order of preference: (a) **surgical reversion** — restore the drifted span to the source's exact wording (a delete/restore, never new phrasing), record it in `semantic-diff.md` §Reverted drift with a verdict of PASS-after-reversion, and leave `body-after.txt` untouched as the raw model record; (b) re-run the script once (fresh sample); (c) stop the topic and report. Never keep a sentence whose factual content the agent cannot certify, and never silently accept a meaning change.
   **Known drift pattern (observed in the 2026-08-21 pilot):** Gemini inserts honorific titles before personal names — e.g. an unattested སློབ་དཔོན་ before ཉི་མ་སྦས་པ in two of five articles. Any title before a personal name that the source sentence does not carry is drift, never a flaggable substitution — the vault's naming doctrine (`wiki-article-from-claims` Rule 17) reserves honorifics for human curation. Walk every personal name in the diff. (Epithets of the *deity* herself — e.g. ཁོང་མ → རྗེ་བཙུན་མ — are flaggable substitutions, not drift.)
9. **`status: draft` always.** Domain experts review the pilot; only a human decides adoption, in-place replacement, or publication. This skill never publishes.
10. **One topic per agent in batch runs** — same batch discipline as `wiki-article-from-claims` Mode B: an agent works only its own topic folder(s), never fans out per-commentary subagents, never writes outside its output folder.

## Procedure

1. **Locate the source.** Confirm `<topic-folder>/article.md` and `<topic-folder>/citations.md` exist. Record the article's `status` and any `wiki_title`/`wiki_pageid` frontmatter (published articles get polished in pilot mode only — the live page is never touched by this skill).
2. **Run the script:**
   ```
   python3 4-SYSTEM/Skills/gemini-article-polish/scripts/gemini_polish.py \
       <topic-folder>/article.md \
       --out 3-TRANSFORMATIONS/Wikipedia/<text-slug>/work/pilot-gemini/<topic>
   ```
   Exit 0 = hard checks pass; exit 2 = still failing after retries → apply Rule 7 (report, stop this topic). Read `gemini-report.md` and note every warning.
3. **Resolve W1 warnings** (paragraph not ending `།།`): if genuine, re-run the script once; if a false positive (e.g. a paragraph ending in a token-adjacent shad pattern), record why in `semantic-diff.md`.
4. **Semantic diff.** Compare `body-before.txt` and `body-after.txt` sentence by sentence and write `semantic-diff.md` per the format above: every fact matched, every ref's attachment confirmed on the same statement, verdict PASS or FAIL. Apply Rule 8 on FAIL.
5. **Complete the folder.** Copy the source `citations.md` into the output folder, appending under the frontmatter a blockquote note: `> [!note] Polished — gemini-article-polish, <date>, model <id>; claim usage unchanged from <source path>.` Then regenerate the preview: `python3 4-SYSTEM/Skills/wiki-article-from-claims/scripts/make_preview.py <out>/article.md`.
6. **Report.** State the output folder, model used, attempts, check results, warnings and how each was resolved, the semantic-diff verdict, and the length delta — the domain expert takes it from there.

## Completion check

- [ ] `article.md`, `citations.md`, `article-preview.md`, `gemini-report.md`, `semantic-diff.md`, `body-before.txt`, `body-after.txt` all present in the output folder
- [ ] Hard checks C1–C7 PASS in `gemini-report.md` (or the topic was stopped and reported, with nothing written to `article.md`)
- [ ] `semantic-diff.md` verdict PASS: no fact added, dropped, changed, or re-attributed; every ref attached to the same statement as before
- [ ] Every verbatim quotation identical character-for-character to the source article
- [ ] Punctuation contract holds in the polished body: no comma, sentence-final shad, paragraph-final `།།`, punctuation before refs
- [ ] Frozen tail, headings, bold spans, category byte-identical to the source
- [ ] Frontmatter carries `polished_by` / `polish_model` / `polish_date` / `polish_source`; `status: draft` unchanged
- [ ] In pilot mode, nothing outside `work/pilot-gemini/<topic>/` was modified; the canonical topic folder and the live wiki page are untouched
- [ ] The API key was never printed, logged, or written to any file

## Dependencies

- **`GEMINI_API_KEY`** in the environment (or a vault-local `.env`, or the shell profile) and
  network access to the Gemini API. The bundled `scripts/gemini_polish.py` uses `urllib`
  only — no SDK, no other third-party package.
- Everything upstream of this skill (`keyword-extract`, `article-subject-filter`,
  `wiki-article-from-claims`) runs without a key; `wiki-article-inventory` needs read-only
  network access to Wikipedia and Wikidata but no key either.
